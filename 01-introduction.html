1  Introduction

In this unit

By the end you will be able to:

  • define an EBV and explain what it is for;
  • name the six EBV classes and recognise how they appear on the portal;
  • explain why the EBVCube stores data as netCDF, and what the format adds;
  • distinguish the four dimensions of an EBVCube from its metrics and scenarios;
  • find and inspect a dataset on the EBV Data Portal.

This unit introduces the concepts you will use throughout the tutorial: what an EBV is, why the EBVCube format uses netCDF, and how a dataset is organised. You need no software yet; we install ebvcube in Unit 2. For now, everything happens in your browser, on the EBV Data Portal.

1.1 What is an Essential Biodiversity Variable?

An Essential Biodiversity Variable (EBV) is a standardised measurement of an important aspect of biodiversity. EBVs provide a common language for describing and tracking biodiversity change across places and time. They can be derived from field observations, remote sensing, or models, and sit between those primary sources and the indicators used for assessment, reporting, and decision making (Group on Earth Observations Biodiversity Observation Network, n.d.; Pereira et al., 2013).

An EBV is not a file. An EBVCube is the standardised file used to store gridded EBV data, together with the information needed to interpret it. Think of the EBV framework as the shared language for biodiversity measurements, and the EBVCube as one way to make those measurements consistent, reusable, and comparable.

1.2 The six EBV classes

EBVs are organised into six classes, each capturing a different dimension of biodiversity:

Genetic composition

Genetic diversity and differentiation within and among populations.

Species populations

Where species occur and how abundant they are.

Species traits

Physical, physiological and behavioural characteristics of organisms.

Community composition tutorial example

The diversity and mix of species within a community.

Ecosystem structure

The physical build and extent of ecosystems.

Ecosystem function

The processes and productivity that keep ecosystems running.

The dataset we use throughout this tutorial, Global trends in biodiversity (BES-SIM cSAR-iDiv), belongs to the Community composition class.

Canonical classes vs. what you see on the portal

The six classes above are the canonical classification defined by GEO BON. On the EBV Data Portal, you may not see all six at once, because the portal lists only the classes represented by available datasets. The portal may also show additional catalogue labels; these do not replace the six canonical EBV classes.

Ecosystem services is not one of the six EBV classes. It belongs to a separate, complementary GEO BON framework, the Essential Ecosystem Service Variables (EESVs), which covers the benefits people obtain from nature rather than biodiversity itself. For the official classification, see the GEO BON definitions page.

1.3 Why netCDF? The EBVCube format

An EBVCube is designed for gridded biodiversity data: values arranged across geographic space and, often, through time. Storing each map or time step as a separate file quickly becomes difficult to manage and interpret. The Network Common Data Form (netCDF), long used in the climate sciences, keeps the data and the information that explains it together in one self-describing file: units, dates, entities, and coordinate reference system travel with the values.

The EBVCube is the standardised, netCDF-based data format defined for EBVs. It follows two established conventions: CF v1.8 (Eaton et al., 2020), which defines how coordinates, units, and time are encoded; and ACDD v1.3 (Earth Science Information Partners, 2015), which defines metadata that makes a dataset easier to discover and understand. EBVCube-specific biodiversity terms complete the format (Quoß et al., 2025).

Every data cube inside an EBVCube shares the same four dimensions. Together, they locate each data value: where, when, and for which biological entity.

Longitude (lon)

The east–west coordinate of the grid, or the projected x-coordinate.

Latitude (lat)

The north–south coordinate of the grid, or the projected y-coordinate.

Time (time)

One date or a whole series: annual, decadal, scenario years, irregular.

Entity (entity)

The biological unit: a species, a group of species, or an ecosystem type.

The entity dimension lets one EBVCube hold data for many species or other biological units at once. Above these four dimensions, metrics and scenarios organise the data cubes inside the file. A metric is what is measured, such as species richness or its uncertainty. A scenario is an optional grouping, normally used for projected data under alternative future pathways.

Our example uses both levels: three scenarios, each with three metrics, make nine data cubes in total. Every one uses the same four dimensions. We return to this hierarchy in Unit 4.

1.4 Touring the EBV Data Portal

Published EBV datasets can be found on the EBV Data Portal. Throughout this tutorial we use one of them as the running example:

Worked example: Global trends in biodiversity (BES-SIM cSAR-iDiv)

id = 30 Community composition DOI 10.25829/5zmy41

Martins, I., Pereira, H. (2022). Global trends in biodiversity (BES-SIM cSAR-iDiv) (Version 1) [Dataset]. German Centre for Integrative Biodiversity Research (iDiv) Halle-Jena-Leipzig. DOI 10.25829/5zmy41 (Martins & Pereira, 2022)

We picked this dataset deliberately. It reports bird species richness for 1900, 2015 and 2050 across three entities (all birds, forest birds, non-forest birds), under three SSP×RCP land-use scenarios. Because it carries both a scenario level and multiple metrics, working through it exposes the entire EBVCube hierarchy — a dataset without scenarios would let you finish the tutorial without ever meeting half the structure.

Open the dataset page and you will find information that supports FAIR (findable, accessible, interoperable, and reusable) use of the dataset:

  • a stable dataset ID (30) and a persistent DOI you can cite;
  • a structured JSON metadata record (title, abstract, EBV class, creators, license, entities);
  • the netCDF file itself, available for direct download (≈ 3.3 MB);
  • an interactive EBV Visualizer for exploring maps and temporal trends without downloading anything.

The three views you will use most are the Discover page (Figure 1.2), an individual dataset page, and the live EBV Visualizer. Click the Discover screenshot to enlarge it.

1.5 Where ebvcube fits

The portal is where EBV data is published and discovered. The ebvcube R package (Quoß et al., 2022, 2025) lets you discover, access, visualise, and create EBVCubes.

DISCOVER
Inspect a published file

Find out what a file contains and how it is organised: list its data-cube paths and inspect its metadata before reading any values.

ACCESS
Read the data you need

Download a published file, read a selected entity or time step, or subset it to a geographic area instead of loading more data than you need.

VISUALISE
Explore patterns and change

Make a map of one data slice or a trend plot through time, without first learning the details of netCDF.

CREATE
Producing new data

Starting from your own rasters or model output, ebvcube assembles them into a valid EBVCube, ready to upload and publish on the portal with its own DOI.

This tutorial concentrates on the path from understanding a published dataset to creating and publishing your own EBVCube, one step at a time.

Checkpoint. Open dataset id = 30 on the portal and identify its EBV class, DOI, entities, and the file formats offered for download. Then identify one scenario and one metric in the dataset. If you can also explain why the data is stored as netCDF rather than as a folder of maps, you are ready to install the software in Unit 2.
